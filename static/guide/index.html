MaternalGuard

A rule-based maternal-health MCP server with a buttons-only clinician dashboard and governed FHIR write-back. Honorable Mention (top 10 of 300+), Agents Assemble — The Healthcare AI Endgame, May 2026.

1 in 25 pregnancies develops severe preeclampsia. MaternalGuard's dashboard turns 5 tool JSON returns into a single one-click huddle — from tool call to accepted FHIR Task in ~2 seconds, with an ONC HTI-1 (b)(11) Decision Support Intervention Provenance every clinician can audit.

Decision support only. MaternalGuard never orders, prescribes, or contacts patients. Every FHIR write is draft-only and requires clinician sign-off. Hackathon prototype; no legal entity backs this artifact.

Why this exists

Roughly 800 US maternal deaths per year, ~60% preventable per the CDC. The most preventable pattern: pre-eclampsia signals evolving silently between visits (rising BP + elevated AST + falling platelets) because a clinician has to open five different chart views to see them together. MaternalGuard reads BP + AST + platelets + conditions + SDOH in one MCP tool call and drafts the MFM consult — with the ACOG citation and the Provenance every draft needs for (b)(11) compliance.

For Prompt Opinion builders (Pawan's copilot thesis)

MaternalGuard maps 1:1 to From 1000 Clicks to Copilots:

  • Buttons-only dashboard: Approve / Reject / Activate / Dismiss. Zero typing. Server supplies the audit reason so the trail stays populated.
  • Optimistic toast on click (instant "Approving: <task>") + green banner at the top of the auto-refreshed huddle — no scrolling to confirm.
  • Multi-tool MCP with 6 tools + A2A wiring: AssessMaternalRisk, InterpretLabTrends, ScreenSocialDeterminants, GenerateCarePlan, PredictNeonatalImpact, ProposeMaternalAction, UpdateMaternalAction, OpenMaternalDashboard, ListMaternalActions.
  • SHARP-on-MCP headers: X-FHIR-Server-URL, X-FHIR-Access-Token, X-Patient-ID. Uses Prompt Opinion's FHIR Context Extension out of the box.
  • Soft-degradation contract: any FHIR read failure returns {status:"no-op", blocksNextStep:false}, never a red banner. The Priority-1 chart-writeback loop always completes.

For (b)(11)-certified stacks like Darena Health (Magnus)

Every governed write emits an HL7 AI Transparency on FHIR Provenance:

  • meta.profile[0] = AI-Provenance, meta.security[0].code = AIAST.
  • Contained AI-Device (aiKind = rule-based, DSI identifier mg-dsi-v0.4.0) linked to a contained AI-ModelCard DocumentReference.
  • The DocumentReference points at the live CHAI Applied Model Card JSON and Markdown served from this same host. No 404s on ONC (b)(11) source-attribute follow.
  • All 13 45 CFR 170.315(b)(11)(iv)(A) Evidence-Based source attributes carried inline on every Provenance for viewers that don't follow references.
  • USCDI v3.1 alignment, HEDIS PPC (NQF #1517) via CPT-II 0500F/0503F on the drafted Task's reasonCode.

Try it in 60 seconds

MaternalGuard is deployed as a Prompt Opinion MCP server. To reproduce the demo:

  1. Register the MCP server in your Prompt Opinion workspace.

    Launchpad → Configuration → MCP Servers → New. Endpoint: https://maternalguard.jonathanandrei.com/mcp. Transport: Streamable HTTP. Auth: API Key, header X-API-Key — contact the publisher for a key. Enable FHIR Context.

  2. Load Maria Santos as the patient.

    Import patient-maria-santos-bundle.json from the repo via Patient Data → Import. Maria is a 28y G2P1 at 32 weeks with evolving HELLP: rising BP (118 → 148 systolic), AST 54 U/L (above pregnancy ceiling), platelets 141 → 100 K/uL, spot proteinuria.

  3. Open the Prenatal Visit Prep agent → New chat → select Maria → send: 
    Draft the appropriate follow-up actions for the current patient.

    The agent chains 5 data tools once each, then ProposeMaternalAction once per RED/YELLOW recommendation, then OpenMaternalDashboard. All in ~3–5 seconds. No red banners. The dashboard renders inline with Approve/Reject buttons per task.

  4. Click Approve on the top task.

    You'll see (a) an instant blue "Approving: <task>" toast, (b) a ~1–2s FHIR round-trip, (c) the huddle re-renders with a green "✓ Approved: <task>" banner at the top. The item disappears from Draft tasks and appears in Recently actioned with an accepted badge.

  5. Verify the FHIR Task and Provenance landed.

    The Postman collection in the repo has pre-wired requests. Import it, paste your workspace bearer, run 2. Tasks → GET Task by ID and 4. Provenance → GET Provenance targeting a Task. The Provenance carries the AI-Transparency profile, the AIAST security label, the contained AI-Device + AI-ModelCard, and the 13 source-attribute inline summary.

Silent success is the point. The most common state after Approve is a Provenance in the store and a task moved to accepted. If the clinician clicks Reject or Dismiss, the audit reason defaults to "Rejected by clinician during huddle review" so the trail is populated without asking anyone to type.

Path to production

Prompt Opinion's own tagline is "Healthcare AI is stuck in pilots. That's not an agent problem. That's an assembly problem." Three concrete next steps to move MaternalGuard out of pilot:

  • CDS Hooks bridge alongside MCP. Darena Health / MeldRx / Epic App Orchard workspaces launch clinical apps via SMART-on-FHIR + CDS Hooks. MaternalGuard's tools port to CDS Hooks in ~1 day of work; the tool logic and Provenance shape stay identical. The same DSI identifier ships against every EHR that speaks SMART.
  • Prospective sensitivity/specificity study against ACOG-benchmarked gold-standard patients. The current 61-case corpus is balanced-but-synthetic. A residency program with an IRB and 200–500 real prenatal charts would move MaternalGuard from Evidence-Based DSI to something with a real ROC curve.
  • Design partnership with an OB residency or MFM service. The buttons-only huddle needs 8–12 weeks in real morning-huddle use to earn its "1 in 25 severe preeclampsia" claim as a measured outcome instead of an epidemiology hook.
Portability: MaternalGuard reads and writes standard FHIR R4 with US-Core-Patient profiles. Point X-FHIR-Server-URL at a MeldRx workspace, Epic App Orchard sandbox, Cerner code sandbox, or a HAPI FHIR store — zero code change. The DSI identifier and CHAI Model Card travel with the app across all four.
